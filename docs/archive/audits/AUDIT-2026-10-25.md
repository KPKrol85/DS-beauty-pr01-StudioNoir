# Studio Noir — Final Technical Front-End Audit

**Audit date:** 2026-10-25

**Archived:** 2026-10-26

**Project:** Static Polish-language portfolio demonstration; Vite multi-page site with vanilla HTML, CSS and JavaScript

**Audit mode:** Final repository and implementation review

**Status:** COMPLETED — all original findings resolved and both optional improvements completed.

Identifiers in this audit are independent of the 2026-10-21 audit archived in `daily-AUDIT-2026-10-24.md`, where P1-01 and P2-01 denote different findings. The original optional items were unnumbered; O-04 and O-05 are the identifiers assigned by the development plan.

## Technical assessment

Studio Noir has a coherent architecture for its documented demonstration scope: six HTML pages, build-time shared header/footer/navigation generation, modular browser interactions, and production-only service-worker registration. Verified strengths include canonical shared markup, Vite build guards, explicit demonstration boundaries, defensive theme/storage handling, and bounded production caching. Booking is a browser-only demonstration that creates, submits and persists nothing.

The initial review passed an in-memory production build and all 83 then-existing Playwright tests, but separately reproduced two short-viewport overlay defects. Initial readiness was therefore **Needs important fixes**; it became **Ready with minor refinements** after PH4-01.

None reported.

## P1 — Important issues

### P1-01 — Mobile menu content becomes unreachable on short viewports

- **Status:** RESOLVED — implemented and verified (PH4-01, `9b484d6`).
- **Original issue:** The fixed, vertically centered mobile panel used `overflow-y: visible` under body scroll lock. At 667×375, 812×375 and 320×256, leading links and lower controls fell outside the viewport, and initial focus landed on an invisible link.
- **Resolution:** A `width < 900px` rule in `css/components.css` makes `.nav__panel` internally scrollable with header-aware padding and auto-margin centering that yields to scrolling. `js/nav.js`, shared markup, dialog ARIA, `inert`, focus wrapping and 900px cleanup are unchanged.
- **Verification:** `npm run build`, `test:nav` (45 passed, including 16 new four-page viewport cases) and `test:mobile-contact-bar` (14 passed); 16 production-preview scenarios reached all nine panel actions by wheel and keyboard. Remote CI later failed intermittently on a breakpoint focus assertion in this coverage; see the archival check.

## P2 — Minor refinements

### P2-01 — Lightbox image collapses to an almost invisible strip at reflow dimensions

- **Status:** RESOLVED — implemented and verified (PH4-02, `338b761`).
- **Original issue:** The 90dvh lightbox grid left the image row about 8px high at 320×256 after controls, caption, padding and gaps.
- **Resolution:** A `max-height: 480px` rule in `css/components.css` reserves a `minmax(50dvh, 1fr)` image row, tightens token spacing and lets the dialog scroll so the caption and controls stay reachable. JavaScript, ARIA, focus behavior and portrait/desktop styling are unchanged.
- **Verification:** Build, `test:interactions` (16 passed, including 6 new viewport/theme cases), `test:mobile-contact-bar` (14 passed) and 8 production-preview lightbox tests passed; the new 320×256 case first failed against the original CSS. All six images were visually inspected at 320×256, 667×375 and 375×812 in both themes and at 1280×800.

## Optional improvements

### O-04 — Reuse an available gallery image when its lightbox alternative is uncached

- **Status:** COMPLETED — implemented and verified (`7f32f9e`).
- **Original issue:** `js/lightbox.js` assigned the thumbnail's fallback `src`; offline, a cached 480px AVIF thumbnail opened an uncached 800px WebP and rendered a 0×0 image.
- **Resolution:** `js/lightbox.js` uses `currentSrc` when the thumbnail is complete with a positive intrinsic width, otherwise `src`, synchronously and without retries. On-demand caching, markup and modal contracts are unchanged.
- **Verification:** Build, `test:interactions` (18 passed), `test:mobile-contact-bar` (14 passed) and 9 production-preview lightbox tests passed. A controlled partial-cache offline scenario reproduced the original failure, then displayed the cached AVIF from cache storage with working controls.

### O-05 — Include the existing reveal and first-paint specifications in CI

- **Status:** COMPLETED — implemented and verified (`20f538e`).
- **Original issue:** CI ran only the navigation, contact-bar and interaction specifications; `tests/reveal.spec.js` and `tests/theme-first-paint.spec.js` were run manually.
- **Resolution:** `package.json` adds `test:reveal` and `test:theme-first-paint`, and `.github/workflows/ci.yml` runs them as separate steps after the original three. Build, Chromium setup, dependencies, permissions, concurrency and timeout are preserved.
- **Verification:** Locally, `test:reveal` (2 passed) and `test:theme-first-paint` (28 passed); workflow YAML and routing were checked statically. At archival, GitHub Actions runs for `20f538e` and `c6e442a` were observed passing all five test steps.

## Verification summary

- **Historical evidence (2026-10-25):** The original review and each follow-up recorded the results above, using preinstalled Windows Chromium: Playwright suites ran against Vite development, while production checks used `npm run preview`. These runs were not repeated during archival.
- **Archival check (2026-10-26):** Source review at `85bbbec` confirmed every correction above is present and unchanged since `20f538e`, together with the matching regressions in `tests/nav.spec.js` and `tests/interactions.spec.js`. No build or test suite was run locally.
- **Remote CI (observed during archival):** GitHub Actions passed for `9b484d6`, `7f32f9e`, `20f538e` and `c6e442a`, but failed for `338b761` and `85bbbec` on one PH4-01 case each: the toggle was not focused after narrowing from 900px to 899px (`tests/nav.spec.js:521`). The equivalent pre-existing assertion (`tests/nav.spec.js:360`) failed the same way before PH4-01, and identical sources passed at `c6e442a`, so the failure is intermittent; it occurs after each case's reachability assertions have passed. It is unresolved.

## Verification limitations

- No live URL was tested; Netlify redirects, response headers, clean URLs and production infrastructure were not verified.
- Browser verification was Windows Chromium only; Firefox, WebKit, physical devices, assistive technologies, forced colors and service-worker upgrade transitions were not verified. CI specifications run against Vite development, not production `dist/`.
- Offline gallery support was verified only in a controlled partial-cache scenario; uncached image variants remain unavailable offline by design.
- Contrast was calculated for four opaque token pairings only. No accessibility certification, performance benchmark, penetration test or dependency vulnerability scan is claimed.
- `THIRD-PARTY-NOTICES.md` leaves the provenance and licensing of several redistributed SVG icons unverified; the legal adequacy of the policy pages was not assessed.
